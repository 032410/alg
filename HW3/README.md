# HW3 — SAT 求解器：用列舉真值表找所有滿足解

程式：[`sat.py`](sat.py)（只用標準函式庫）

```bash
python sat.py "(a & b) | ~c"      # 求解 + 印出真值表
python sat.py "(a & b) | ~c" --all   # 完整印出（列數 <= 64 時）才需要
python sat.py --demo                 # 跑 5 個內建範例
```

## SAT 問題在講什麼

給定一個布林公式（例如 `(a & b) | ~c`），問：**有沒有辦法把每個變數代入 true/false，
讓整個公式變成 true？**

- **指派（assignment）**：把每個變數定成 0 或 1
- **滿足解（model / satisfying assignment）**：代入後公式為 true 的那組指派
- **SAT**：至少有一組滿足解
- **UNSAT**：一組都沒有（公式是矛盾式，例如 `a & ~a`）

由於「n 個變數」共有 2ⁿ 種指派，**最笨但一定正確的办法就是把真值表完整列舉一遍**，
每一列算一次公式，看結果是不是 1。這個程式的核心就是這件事。

## 程式怎麼運作

```
字串 "  (a & b) | ~c  "
   │  ① tokenize()      切成 ( ( a & b ) | ~ c )
   │  ② parse_formula() 遞迴下降解析成 AST
   ▼
   ('or', ('and', ('var','a'), ('var','b')), ('not', ('var','c')))
   │  ③ 收集變數 → n = 3 → 需要 2³ = 8 列
   │  ④ 兩種求值方式，結果必須一致（自我驗證）
   ▼
SAT / UNSAT + 所有滿足解
```

支援的語法：

| 寫法 | 意義 |
| --- | --- |
| `a` | 變數（多字母也可以，如 `x1`、`is_ok`） |
| `&` `&&` `AND` | 且 |
| `\|` `\|\|` `OR` | 或 |
| `^` `XOR` | 互斥或 |
| `!` `~` `NOT` | 否 |
| `0` `1` `TRUE` `FALSE` | 常數 |
| `( )` | 優先序（`!` > `&` > `^` > `\|`） |

### 兩種求值方式

**方法 A：逐列列舉（`evaluate`）** — 就是HW1 教的 brute force：

```python
for r in range(2 ** n):                 # 系統性列舉每一列
    env = {name: (r >> i) & 1 for ...}  # 第 i 個變數 = 第 i 個位元
    if evaluate(node, env):             # 算這一列的公式值
        models.append(r)
```

**方法 B：位元並行（`evaluate_bitmap`）** — 整張真值表用一個大整數一次算完。
Python 的 `int` 是任意長度，`2²⁴` 個 bit 就是一個 2 MB 的整數，所以：

```python
columns = {name: column_bits(i, rows) for i, name in enumerate(variables)}
bitmap  = evaluate_bitmap(node, columns, mask)   # bit r = 第 r 列的公式值
```

- 每個變數的「整欄」用位元組塞好：變數 i 的欄是 `2^i` 個 0 接 `2^i` 個 1，一直重複
- `&`、`|`、`~` 直接對這些大整數做運算 → 等於同時對整欄做布林運算
- `~` 要記得用 `& mask` 截斷（Python 的 `~` 會補位到負數）
- 最後 `set_bits()` 用位元組掃描取出所有 1 的位置（不要逐 bit `>>`，那會變 O(rows²)）

程式兩種都跑並互相比對，輸出「【驗證】逐列 enumerate 的結果與真值表一致：True」。

## 實測

`x0 & x1 & ... & x23 | ~x0`（24 個變數，2²⁴ = 16,777,216 列）：

```
真值表列數 = 2^24 = 16,777,216
【結果】SAT —— 共有 8,388,609 組滿足解
【時間】1120.9 ms
```

20 個變數（1,048,576 列）兩種做法的比較：

| 做法 | 耗時 |
| --- | --- |
| 逐列 `evaluate` + 逐列組指派 | 約 7,100 ms |
| 位元並行 `evaluate_bitmap` | **324 ms**（約快 22 倍） |

差在：方法 A 每列都要呼叫一次 Python 函式（overhead 很大），方法 B 把 2ⁿ 個布林運算
壓成 2ⁿ/64 次 C 層的大整數運算。**但兩者都還是 O(2ⁿ)**，只是常数差很多。

## 複雜度與極限

- 公式有 n 個變數、長度 m：時間 `O(2ⁿ · m)`、空間 `O(2ⁿ)`
- 這就是 **SAT 是 NP-complete** 的原因：最壞情況一定要看過 2ⁿ 種指派
  （P ≠ NP 的假設下沒有保證更快的演算法）
- 實務上 n 的上限：大約 **n ≤ 25** 還能秒收（2²⁵ ≈ 3,300 萬列），
  n = 40 就是 1 兆列，跑一輩子
- 所以真正的 SAT solver（MiniSat、CDCL、Google SAT）用 **DPLL + 子句學習**，
  靠「剪枝」平均只看千分之一的指派；維基百科、晶片驗證、拼圖求解都靠它

## 範例輸出

```
$ python sat.py "(a & ~b) | (b & ~c) | (c & ~a)" --all
公式：(a & ~b) | (b & ~c) | (c & ~a)
變數（3 個）：a, b, c
真值表列數 = 2^3 = 8

【真值表】第 i 個變數對應位元 i（0 = 假，1 = 真）
  列     a   b   c  |  結果
  ----------------------
    0     0   0   0  |   0
    1     1   0   0  |   1   <- 滿足解
    2     0   1   0  |   1   <- 滿足解
    3     1   1   0  |   1   <- 滿足解
    4     0   0   1  |   1   <- 滿足解
    5     1   0   1  |   1   <- 滿足解
    6     0   1   1  |   1   <- 滿足解
    7     1   1   1  |   0

【結果】
  SAT —— 共有 6 組滿足解（全部都要 SAT 才算 UNSAT）
【驗證】逐列 enumerate 的結果與真值表一致：True
```

`a & ~a` 會得到 **UNSAT**（兩列都是 0，沒有滿足解）。

## 對應到 HW1 / HW2 學到的東西

| 本題 | 對應觀念 |
| --- | --- |
| 列舉 2ⁿ 種指派 | HW2 的 `T(n) = 2T(n-1) + 9` → `Θ(2ⁿ)`，指數時間 |
| `for r in range(2 ** n)` | HW1 的方法 2a：2ⁿ 次呼叫，n 大就跑不完 |
| 剪枝、只用必要指派 | 就是 DPLL 的概念，能把指數降成平均很快 |
