# HW1 — power2n：四種寫法的比較

計算 `2**n`，分別用四種寫法實作，測試 `n = 100`，比較速度並找出哪一種「跑不出來」。

- 程式：[`power2n.py`](power2n.py)
- 執行：`python power2n.py`（只用標準函式庫，不需要安裝任何套件）

## 四種方法

| 方法 | 函式 | 想法 | 函式呼叫次數 | 時間複雜度 | 遞迴深度 |
| --- | --- | --- | --- | --- | --- |
| 方法 1 | `power2n_1` | `2 ** n` 運算子 | 1 | 極快（C 層大數運算） | 0 |
| 方法 2a | `power2n_2a` | `f(n-1) + f(n-1)` | 2ⁿ | 指數時間 O(2ⁿ) | n |
| 方法 2b | `power2n_2b` | `2 * f(n-1)` | n + 1 | 線性 O(n) | n + 1 |
| 方法 3 | `power2n_3` | 遞迴 + 查表（記憶化） | 2n | 線性 O(n) | n |

> 題目原本讓四個方法都叫 `power2n`，後面的定義會覆蓋前面的，只剩最後一個能測。
> 為了「每個函式都要測」，這裡改成 `power2n_1 / 2a / 2b / 3` 四個不同的名字。

## 執行結果（本機：Python 3.12.10）

### 1. n = 100 的速度比較（每個方法重複 2000 次取平均）

```
方法                    花費時間      排序   說明
------------------------------------------------------------------
方法1 **            0.213 ms       1   O(1) 層級，C 層大數運算（每次 0.107 us）
方法2b 遞迴          11.444 ms       2   n+1 = 101 層 Python 遞迴（每次 5.722 us）
方法3 查表           29.330 ms       3   n = 100 層，但只呼叫 200 次（每次 14.665 us）
```

- **方法 1 最快**：`2 ** 100` 只有一次運算，Python 的大數乘法在 C 層完成。
- **方法 2b 次之**：只有 n+1 = 101 次呼叫，但每次呼叫都有 Python 函式呼叫 + 遞迴的額外成本。
- **方法 3 反而比 2b 慢**：雖然只要 200 次呼叫，但每次都要做 `if table[n] == 0` 的判斷與 list 取值；
  這種寫法省的是「重複計算」，n=100 時本來就沒有重複好省，所以優勢看不出來（n 很大時才有意義）。

### 2. 方法 2a：n = 100 跑不出來

```
   n            理論呼叫次數            實測
--------------------------------------
  10             1,024      0.076 ms
  15            32,768      3.362 ms
  20         1,048,576    102.877 ms
  22         4,194,304    399.763 ms
  24        16,777,216   1441.729 ms
  26        67,108,864       timeout  <- 超過 5 秒，放棄
  30     1,073,741,824       timeout  <- 超過 5 秒，放棄
  40 1,099,511,627,776       timeout  <- 超過 5 秒，放棄
 100         1.268e+30       timeout  <- 超過 5 秒，放棄
```

- `f(n) = f(n-1) + f(n-1)` 會呼叫 `f(n-1)` **兩次**，而這兩次的結果一模一樣卻都重算，
  導致呼叫次數是 `2^n`。實測 n 每加 1，時間大約乘 2（指數成長）。
- `n = 100` 需要呼叫 2¹⁰⁰ ≈ 1.268 × 10³⁰ 次。就算每次呼叫只要 1 ns，也要花 10²² 年以上。
- 所以 **方法 2a 在 n = 100 時是「跑不出來」的那一個**。
- 為了不要卡死整個程式，方法 2a 是在獨立行程（`multiprocessing.Process`）裡執行並加上 5 秒逾時，
  超時就 `terminate()` 掉。改小 n（例如 n ≤ 24）就能順利跑完。

### 3. 結果正確性

```
方法1 / 2b / 3 == 2**100 ? True
方法2a 在 n = 100 : timeout
```

四種寫法在 n = 100 時結果都等於 `1267650600228229401496703205376`（31 位數），
只是方法 2a 根本算不完。

### 4. 另一個會出錯的地方：遞迴深度

```
方法2b 遞迴 在 n = 5000 (> 遞迴上限) : RecursionError: maximum recursion depth exceeded
方法3 查表 在 n = 5000 (> 遞迴上限) : RecursionError: maximum recursion depth exceeded
方法1 在 n = 10000000 : 10000001 個 bit（沒有遞迴限制，照樣算得出來）
```

遞迴寫法要能用的前提是 `n` 不能太大：Python 的遞迴上限預設是 1000 層，
`power2n_2b(1000)` 就會爆掉。方法 1 沒有這個問題。

## 結論

1. **最快：方法 1**（`2 ** n`）。能不用遞迴就不用。
2. **方法 2a 永遠不要用**：`f(n-1) + f(n-1)` 是最自然的遞迴寫法，卻是指數時間，
   寫錯了就從 O(n) 變成 O(2ⁿ)。若真的需要這種拆法，必須配上記憶化（方法 3）。
3. **方法 3（查表）的重點**：只在函式外面建表沒有用，還要在函式**裡面先查表**：

   ```python
   if table[n] == 0:                      # 沒算過才遞迴
       table[n] = power2n_3(n-1, table) + power2n_3(n-1, table)
   return table[n]                        # 算過就直接查表
   ```

   若省略那個 `if`，每次還是呼叫兩次 `f(n-1)`，呼叫次數依然是 2ⁿ（只是值被重複算了 n 次）。
4. **寫遞迴前先想呼叫次數**：`n` 層 = O(n)，`2ⁿ` 層 = O(2ⁿ)，差異是十的三十次方等級。

## 程式結構

```python
power2n_1(n)                 # 方法 1
power2n_2a(n)                # 方法 2a：指數時間
power2n_2b(n)                # 方法 2b：遞迴乘 2
power2n_3(n, table=None)     # 方法 3：遞迴 + 查表

_worker(func, n, q)          # 在子行程執行並回傳結果／例外
timed_call(func, n, timeout) # 帶逾時的計時（避免指數時間卡死主程式）
bench(func, n, repeat)       # 重複計時，算出每次呼叫平均耗時
main()                       # 主程式：跑上面所有測試並印出比較表
```
